# AI Intel Hub -- Design Doc v1

> 双引擎方案：vault 知识编织 + 轻量内容管线

**Author:** muming | **Date:** 2026-03-21 | **Status:** Draft

---

## 1. 问题定义

muming 是 AI PM，需要每天追踪 AI 行业前沿。现状：

- **信息源分散**：公众号、Claude Blog、HN、Reddit、KOL Twitter -- 东看一眼西看一眼
- **看了就散了**：信息消费后没有沉淀到 vault 知识架构上，无法形成关联和深度
- **深入不下去**：知道发生了什么，但不知道这件事和自己已有认知的关系、前因后果
- **三线需求并行**：自用掌握动态 + 公司汇报/商机判断 + 个人自媒体内容

**核心痛点一句话**：碎片信息挂不上知识架构，看得多但认知没增长。

**现有竞争对手**（即当前土办法）：偶尔刷公众号 + 手动跑 /ai-industry-intel-digest + 直接看 Claude Blog。无固定流程，无自动化，无沉淀。

## 3. 架构：双引擎

```
信息源（14 源）
    | collect.py（已有）
    v
原始素材池（SQLite intel.db）
    | AI 筛选（信号强度评分，6 分以上）
    v
精选情报（每日 5-15 条）
    |
    +---> 引擎 1: 知识编织器 -----> vault/ 原子笔记
    |     (核心价值)                  - 自动 wikilink 关联
    |                                 - 挂到已有知识节点
    |                                 - Obsidian 里即时可见
    |
    +---> 引擎 2: 内容管线 ------> 发布素材
          (增值输出)                  - 每日简报（飞书/本地）
                                     - 深度解读（vault + 飞书）
                                     - 小红书/B站素材
```

---

## 4. 引擎 1: 知识编织器（核心，Phase 1 交付）

### 4.1 做什么

对每条精选情报（6 分+），AI 做三件事：

1. **分类**：判断属于哪个知识域（ai-frontier / competitor / opportunity / product-lab / methodology）
2. **关联**：在 vault 中搜索相关文件，生成 2-3 条 wikilink
3. **写入**：生成一篇原子笔记（200-500 字），首行是判断/观点，写入 vault 对应目录

### 4.2 原子笔记格式

```markdown
---
source: {source_label}
url: {url}
signal_score: {score}
date: {YYYY-MM-DD}
tags: [ai-intel, {domain}]
---

{一句话判断 -- 这件事意味着什么}

## 事件

{发生了什么，2-3 句}

## 关联

- [[已有文件A]] -- {为什么相关}
- [[已有文件B]] -- {为什么相关}

## 我的看法

{AI 基于 vault 上下文给出的解读，这对 muming 作为 AI PM 意味着什么}
```

### 4.3 编织流程

```python
for item in today_items(score >= 6):
    1. 用 GLM/DeepSeek 判断 domain 分类
    2. grep vault/ 找相关文件（关键词匹配 + 文件名匹配）
    3. 读取 top 3 相关文件的首行摘要
    4. 用 Claude API 生成原子笔记（带 wikilink + 解读）
    5. 写入 vault/1-knowledge/{domain}/intel-{date}-{slug}.md
    6. 更新 vault/05_Inbox/daily-intel-{date}.md（今日索引）
```

### 4.4 每日索引文件

每天在 `vault/05_Inbox/` 生成一个索引：

```markdown
# AI 情报 | 2026-03-21

今日编织 8 条情报，深度级 2 条。

## 深度级（10 分+）
- [[intel-20260321-claude-sonnet-4-6]] -- Anthropic 发布 Claude Sonnet 4.6
- [[intel-20260321-meta-mtia-chips]] -- Meta 自研 AI 芯片量产

## 标准级（6-9 分）
- [[intel-20260321-hn-top1]] -- ...
- ...

## 知识架构更新
- ai-frontier/: +3 篇
- competitor/: +1 篇
- opportunity/: +2 篇，触发商机重评分
```

## 5. 引擎 2: 内容管线（增值，Phase 2 交付）

### 5.1 三种输出

| 输出 | 格式 | 频率 | 消费者 |
|------|------|------|--------|
| **每日简报** | 飞书文档 / vault md | 每日 | 自己 + 公司 |
| **深度解读** | vault md + 飞书 | 每周 2-3 篇 | 自己 + 公众 |
| **自媒体素材** | 小红书图文 / B站文章 | 每周 3-5 篇 | 小红书/B站粉丝 |

### 5.2 内容生成流程

```
vault 今日原子笔记（引擎 1 产出）
    |
    +---> 每日简报：聚合今日所有原子笔记 → 提炼 3-5 条核心 → 生成提词稿
    |
    +---> 深度解读：挑 10 分+ 情报 → 读关联 vault 文件 → 写 3000-5000 字叙事
    |
    +---> 自媒体素材：从深度解读 → 改写为平台适配格式（小红书 800 字 + 标签）
```

### 5.3 与已有 Skill 的关系

- **每日简报** = 复用 /brief 的提词稿格式
- **深度解读** = 复用 /ai-industry-intel-digest 的写作风格
- **自媒体素材** = 复用 /geo-content 的平台适配逻辑

不重新造轮子，通过 vault 原子笔记串联已有 Skill。

## 6. Dashboard 改造

从"信息展示面板"改为"编织状态页"：

- **今日编织状态**：编织了几条、写入了哪些目录、关联了哪些已有文件
- **知识架构热力图**：哪些域最近更新频繁、哪些域长期沉寂
- **待审阅队列**：AI 编织的笔记可能有错，人工审阅后标记确认
- **内容管线状态**：今日简报是否生成、深度解读进度、待发布素材

## 7. 分阶段交付

### Phase 1: 知识编织器（MVP，本周交付）

| 步骤 | 交付物 | 验证标准 |
|------|--------|---------|
| 1.1 | AI 筛选（已有评分 + GLM 分类） | 268 条 → 筛出 20-30 条精选 |

**Phase 1 成功标准**：每天早上打开 Obsidian，05_Inbox/ 里有一个今日情报索引，点进去每条都有 wikilink 关联到已有知识。

## 8. 技术选型

| 组件 | 选择 | 理由 |
|------|------|------|
| 采集 | collect.py（已有） | 14 源已验证 |
| AI 筛选/分类 | GLM-5-turbo / DeepSeek | 成本低，分类任务质量够 |
| 知识编织 | Claude API | 需要理解 vault 上下文 + 高质量写作 |
| 存储 | vault/ (md files) + intel.db (SQLite) | vault = 知识层，SQLite = 元数据层 |
| 消费 | Obsidian（主力）+ Dashboard（状态） | 不强制用户换工具 |
| 自动化 | cron + 桌面通知 | 已有基础设施 |

### API 成本估算（按 CLAUDE.md 成本控制原则）

| 步骤 | 模型 | 每日调用量 | 成本/天 |
|------|------|----------|---------|
| 分类 | GLM-5-turbo | 30 条 x 200 token | ~$0.01 |
| 关联搜索 | 本地 grep | 30 次 | $0 |
| 编织生成 | DeepSeek | 15 条 x 800 token | ~$0.02 |
| 深度解读 | Claude API | 2 条 x 3000 token | ~$0.10 |
| **合计** | | | **~$0.13/天** |

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| wikilink 关联不准确 | 噪音笔记污染 vault | 人工审阅队列 + 置信度标注 |
| 原子笔记质量低 | 不如手动写 | 首行必须是判断/观点，不是复述 |
| vault 文件膨胀 | Obsidian 变慢 | 每月归档旧情报到 archive/ |
| API 成本失控 | 超预算 | GLM/DeepSeek 优先，Claude 只用于深度 |

## 10. 与 plan-v1.md 的关系

plan-v1.md 的 5 阶段计划在本设计中的映射：

| plan-v1 | 本设计 | 状态 |
|---------|--------|------|
| Phase 1: 采集 + 面板 | 采集层（已完成）+ Dashboard（改造） | 底层完成 |
| Phase 2: 三流合一 | 引擎 1 知识编织 | **本次核心** |
| Phase 3: 内容工厂 | 引擎 2 内容管线 | Phase 2 |
| Phase 4: 半自动发布 | Phase 3 闭环 | 后续 |
| Phase 5: 全自动飞轮 | cron 端到端 | 后续 |

**关键变化**：plan-v1 是"采集→展示→发布"的线性管线，本设计把"知识编织"插入为核心环节，从"信息搬运"升级为"知识增长"。
